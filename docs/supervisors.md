# For supervisors

verifiedmethods units are free, and you can use them in whatever way suits your
students. Most supervisors will use a unit in one of two ways:

As a starting point for a project
: The student works through the unit, then takes one of its project briefs, or
  a question of your own, as the project.

As a check on a project you have already set
: The student uses the unit's method and checks for the computational part of
  their project, and includes the verification report in the appendix.

## Adopting a unit

1. Download the unit (for example [A1](units/ode-ivp/index.md)) and try
   `python verify.py` yourself; it takes about ten minutes.
2. Give the zip file to your students, or point them to this site.
3. Agree a project brief with each student. Each brief states what counts as
   the student's own contribution.
4. When a student submits, confirm the report and ask a few viva questions.

## What you get

| | |
|---|---|
| How to confirm a report | Two minutes, in your own copy of the unit |
| Viva questions | Twelve for unit A1, on the code, the results and the project |
| Marking rubric | For the computational chapter, with suggested weights |
| AI-use statement | A short statement you can adopt or adapt |
| Marking guides for the briefs | On request: email from your institutional address (see [About](about.md)) |

For unit A1 these are in [the supervisor material](units/ode-ivp/supervisors/index.md).

## What we ask in return

The units are new, and your comments shape them. If you use a unit, please tell
us what worked, what confused your students, and which methods you would like
covered next. See [About](about.md).
